# Правила работы агента

- Работа идёт фазами: согласование → реализация → проверка → коммит. План и статусы — в
  `docs/plans/ui-test-project.md`, он обновляется после каждой фазы.
- «Написал конфиг» ≠ «проверил работу». Статус отмечается только по фактическому
  результату: команда, exit code, реальный запуск или артефакт.
- Версии закреплены и проверены по checksum (Gradle Wrapper 9.2.0, Allure CLI 2.46.1,
  Actions — по полным SHA). `latest` и плавающие диапазоны не добавлять.
- Секреты — только через env/параметры/secrets CI; не в коде, не в логах, не в
  артефактах. `.env`, `.ci-secrets.env`, `build/`, `.tools/` — в `.gitignore`.
- Никаких ретраев, `@Disabled`, `continue-on-error` для маскировки падений: упавший
  шаг тестов оставляет job красным, exit codes сохраняются.
- Ошибка уведомления не может менять исход тестов: отправитель Telegram изолирован
  (`continue-on-error` только у job `notify-telegram`, `exit 0` в `jenkins-telegram.ps1`).
- Временная диагностика и контролируемые падения — на временных ветках; в `main`
  не переносятся и удаляются после проверки.
- Commit, push, публикация, запуски CI и реальные отправки уведомлений — только после
  отдельного разрешения пользователя.
- Команды запуска, параметры и пути отчётов — в `README.md`.
