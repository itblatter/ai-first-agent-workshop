# Ретроспектива: где AI ошибся и как это заметили

Каждая строка — реальный случай из истории этого репозитория (коммиты и номера
сборок указаны в `docs/plans/ui-test-project.md`).

| Ошибка / неточное предположение агента | Как заметили | Какая проверка поймала бы раньше |
|---|---|---|
| Валидация `browserSize` в workflow использовала якорь `$` — в .NET он допускает совпадение перед завершающим LF, и `1920x1080\n` проходил проверку | Целевой негативный сценарий на извлечённом из YAML блоке до первого push; исправлено на `\A…\z` | Таблица граничных входов с управляющими символами (LF/CRLF) на этапе локальной проверки workflow, а не после |
| Читатель JUnit XML для уведомлений использовал `.Name` — PowerShell XML-адаптер возвращает атрибут `name`, а не имя элемента; evidence классифицировался бы неверно | Прогон `test-ci-telegram.ps1` на реальном JUnit XML, скачанном из артефактов CI, а не на синтетическом fixture | С самого начала использовать настоящие CI-артефакты как fixtures вместо «похожих» XML |
| Предполагалось, что password-параметры Jenkins применяют свои дефолты при API-запуске — на деле `build`/`buildWithParameters` с пустыми полями передают пустые значения | Реальный build 8 упал с `parameter not set` | Обязательный API-triggered прогон-проверка параметров до написания логики секретов |
| Предполагалось, что в Groovy sandbox работают `env[key]=` и `String.eachLine` с CPS-замыканием — `putAt` отклонён (build 15), `eachLine` обрывался после первой строки (build 16) | Падение реальных сборок на агенте | Минимальный probe-pipeline с `sandbox: true` на теле скрипта до полного pipeline |
| Считалось, что у агента стабильный egress до `api.telegram.org` — DNS-эндпоинт таймаутил, известные IP отвечали выборочно | Предупреждения о недоставке в реальных сборках (окно полного таймаута — build 11) | Зондирование конкретных egress-точек ещё в диагностическом build 1, а не только HEAD-проверки github/maven |
| Установщик `setup-allure.ps1` предполагал Windows (`java.exe`, `allure.bat`) — пришлось адаптировать под Linux-агент | Попытка переиспользования на агенте | Требование «скрипт обязан работать на целевой ОС агента» в согласовании фазы 7 до реализации |
| Реализация фаз 1–5 жила в незакоммиченном рабочем дереве исходного клона — «зелёная машина» не была воспроизводимым состоянием | `git status` на финальном mini-review | Коммит после каждой проверенной фазы (правило задания) — тогда дерево фазы == коммиту фазы |

## Общий вывод

Наличие файла не равно работоспособности: Jenkinsfile прошёл linter, но реальные
сборки вскрыли sandbox-ограничения и особенности API-параметров, которые статика
не показывает. Аналогично, локальная модель условий workflow не заменила прогон
движком Actions — контролируемое падение проверялось настоящим run с артефактами.
Самая полезная привычка: проверять настоящие артефакты и выполнять
контролируемые падения, а не читать код и предполагать результат.
